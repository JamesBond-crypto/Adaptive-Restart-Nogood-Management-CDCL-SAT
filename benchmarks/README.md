# Benchmark Suites, Provenance & Redistribution Permissions

This directory houses the DIMACS-format Boolean Satisfiability (CNF) benchmark instances utilized for empirical evaluation across developmental and holdout testing campaigns.

---

## 1. Benchmark Suites & Evaluation Subsets

To ensure scientific precision, this catalog distinguishes the physical files hosted in the repository from the exact factorial evaluation subsets verified in the raw master CSV records:

| Suite Identifier | Subdirectory | Files in Public Repository | Evaluated Subset in Experiments | Experimental Design & Runs | Primary Purpose |
| :--- | :--- | :---: | :---: | :---: | :--- |
| **Smoke Test** | `smoke_test/` | 2 CNF files | 2 instances | 2 runs (1 configuration, 1 repetition) | Rapid unit-test sanity verification (<0.01 s) |
| **Pilot Suite** | `pilot/` | 20 CNF files | 20 instances | Calibration trials (baseline vs. pilot adapt) | Initial solver calibration and boundary tuning |
| **Development Suite** | `expanded/` | 36 CNF files | **36 instances** | **6 configurations × 3 repetitions = 648 runs** | Factorial development evaluation (`v3_full_development`) |
| **Unseen Holdout Suite** | `final_holdout/` | 8 scripts & manifests *(CNFs fetched on-demand)* | **48 instances** | **8 configurations × 3 repetitions = 1,152 runs** | Quarantined validation (`final_holdout/master_results.csv`) |

### Verification Against Raw CSV Datasets
- **Development Master Record:** [`experiments/results/qre_gated_full_development/master_results.csv`](../experiments/results/qre_gated_full_development/master_results.csv) contains exactly **648 run records** (36 unique instances × 6 solver configurations × 3 random seeds; 102/108 solved for baseline and V3+AdaptFix, PAR-2 2.7463 s vs 2.5381 s).
- **Holdout Master Record:** [`experiments/results/final_holdout/master_results.csv`](../experiments/results/final_holdout/master_results.csv) contains exactly **1,152 run records** (48 unique benchmark instances across 7 problem families × 8 solver configurations × 3 repetitions; 144/144 solved for all configurations, PAR-2 0.1208 s vs 0.1107 s).

## 2. Redistribution Rights and Open-Access Provenance

### A. SATLIB and DIMACS Challenge Benchmarks (`final_holdout/`)
- **Primary Source:** [SATLIB — The Benchmark Library](https://www.cs.ubc.ca/~hoos/SATLIB/) (Hoos & Stützle, 2000), University of British Columbia.
- **Problem Families & Historical Origins:**
  - **AIM (`aim-*`):** Artificially created 3-SAT instances with known solution counts by Kazuo Asahiro, Kazuo Iwama, and Eiji Miyano (1993, Second DIMACS Implementation Challenge).
  - **Dubois (`dubois*`):** Hard, structured random contradiction instances designed by Olivier Dubois (1993, Second DIMACS Implementation Challenge).
  - **Flat (`flat100-*`, `flat150-*`):** Hard, flat graph 3-coloring instances generated by Joseph Culberson (1995, Second DIMACS Implementation Challenge).
  - **Pretolani (`pret*`):** 2-CF instances with embedded hidden contradictions by Francesco Pretolani (1993, Second DIMACS Implementation Challenge).
  - **Logistics & Hanoi (`logistics.*`, `hanoi*`):** Discrete deterministic planning problems encoded into CNF by Henry Kautz and Bart Selman (1996).
  - **Bridging Faults (`bf*`):** Circuit bridging-fault test generation benchmarks by M. Aihara (1993, Second DIMACS Implementation Challenge).
- **Redistribution Policy & Clean-Room Hosting:**
  - Because SATLIB and DIMACS benchmarks lack an explicit open-source or public-domain redistribution license for public hosting, raw third-party CNF files are excluded from this public repository.
  - **Autonomous Acquisition Harness:** The complete 48-instance holdout suite can be fetched and cryptographically verified directly from upstream archives in ~15 seconds using the provided scripts:
    ```bash
    python benchmarks/final_holdout/acquire_holdout_suite.py
    python benchmarks/final_holdout/validate_holdout_suite.py
    ```
  - **Authoritative Citation:**
    > Holger H. Hoos and Thomas Stützle, *"SATLIB: An online resource for research on SAT"*, in *Satisfiability Handling: Codenames, Selected Papers*, Kluwer Academic Publishers, pp. 283–292, 2000.
